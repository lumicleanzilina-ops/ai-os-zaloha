# Známá omezení a řešení

## Kit 4.4
Přesný obsah a otisky souborů určuje `release-manifest.json` této distribuce. Dashboard 4.4 je samostatný druhý ZIP: vychází spolu s Kitem 4.4 a navazuje na hotový Kit 4.4.

- Pro technické nástroje použij Node 24 a Git. Nový Kit má pojistky nejprve neaktivní; jejich aktivaci a ověření vede agent podle [SETUP](SETUP.md). Text pravidel se načítá i přes CLAUDE.md → @AGENTS.md.
- Staré aktivní hooky mohou bez Gitu blokovat opravu. Otevři novou session nad čerstvě rozbaleným Kitem, který hooky ještě nezapnul; agent připraví chybějící Git a po záloze opraví pouze příslušné projektové nastavení. Nepřepisuj osobní pravidla ani globální nastavení, nevypínej hlídač tajemství.
- Claude hooky nejsou automaticky hooky Codexu či jiného hosta. Při předání musí agent zaznamenat skutečně ověřený rozsah, nikoli univerzální slib.
- Git záloha neobsahuje ignorované soubory, credentials, externí vault ani vnořená repozitáře bez jejich vlastní konfigurace. Obnovu konkrétního výsledku ověř do nové složky. Velká média mohou vyžadovat samostatnou zálohu mimo Git.
- Nativní Windows průchod a úplný onboarding nezávislého začátečníka nejsou doložené lokálními macOS testy. Aktuální doklad vydání uvádí přesný rozsah testů.
- Plánované úlohy (ranní rutina): postup pro Claude Desktop je ověřený podle oficiální dokumentace ([postup](../scheduled-tasks/README.md#ranní-rutina-v-claude-desktopu)). Neověřené zůstává nativní Windows a cloudové úlohy (routines) bez repozitáře na GitHubu: cloudová úloha pracuje s čerstvou kopií repozitáře, ne s pracovní složkou.
- Dovednosti jako příkazy na nativním Windows: `tools/zpristupnit-skilly.mjs` tam zakládá kopie se značkou místo symlinků. Větev je ověřená jen testem s nasimulovanou platformou na macOS; skutečný běh na Windows a načtení kopií Claude Desktopem doložené není.
- Obal testů `tools/beh.mjs` na nativním Windows: spuštění `npm`, `npx`, `vitest` nebo `playwright` (soubory `.cmd` a `.bat`) přes `cmd.exe` je ověřené jen simulací výběru programu a uvozování na macOS. Skutečný běh na Windows, včetně úklidu složky a ukončení potomka, doložený není. Argument s uvozovkou nebo `%` obal pro `.cmd` a `.bat` odmítne s hláškou; takový program spusť přímo (`node`, `.exe`).
- Předání do Dashboardu z nativního Windows: `tools/kit-completion.mjs` tam soukromí dokladu ověřuje podle ACL souboru (číst smí jen tvůj účet, SYSTEM a Administrators), ne podle POSIX práv 0600. Export proto zakládej v novém místě ve svém uživatelském profilu, například v `%LOCALAPPDATA%`; sdílené místo kontrola odmítne dřív, než v něm cokoli založí. Leží-li workspace mimo profil na disku NTFS, nepřesouvej ho: hláška dá přesný příkaz `icacls`, který omezí jen složku dokladu `.ai-os` (spustit ve Windows PowerShellu nebo v cmd, ne v Git Bash). Na FAT32 nebo exFAT (USB disk, paměťová karta) `icacls` nefunguje, workspace i export tam patří do profilu (`%USERPROFILE%`) na NTFS. Ve WSL nedrž workspace na `/mnt/c`: práva 0600 se tam obvykle neudrží. Kontrolu nevypínej. Na skutečném Windows ani při přenosu exportu do WSL to zatím ověřené není.

## Dashboard je samostatná nadstavba v betě
Dashboard není nutný pro Kit. Dashboard 4.4 je beta pro kupující Kitu v druhém ZIPu, včetně upravitelných zdrojů aplikace; navazuje na hotový Kit 4.4 a začíná až po [předání](PREDANI-DASHBOARDU.md) hotového Kitu. Jeho vlastní stav distribuce a kvalifikace má přednost před obecnými zmínkami v Kitu: licenci, meze bety a skutečně ověřené platformy uvádí jeho balík (`LICENSE.md`, `modules/aplikace/vydani.json`). Skutečným průchodem zatím nejsou doložené Windows přes WSL2, čistý VPS, tailnet a telefon, živá inference Jevu a nativní callback desktopových klientů; agent je nevydává za hotové. Instalátory a spouštěče celého stacku technicky ověřují soukromý doklad Kitu `.ai-os/kit-completion.json` a otisky jeho důkazů; bez platného dokladu nic nenainstalují ani nespustí. Obsah protokolu a skutečné dokončení průvodce ověřuje agent.

## Když něco selže
Agent řekne konkrétní neověřený krok, uchová dosavadní nastavení a dá jeden další krok. Uložený soubor, běžící proces, přihlášení a úspěšný skutečný úkol jsou rozdílné důkazy. Tajemství do diagnostického reportu ani do chatu nepatří.
