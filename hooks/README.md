# NODE HOOKY A OVĚŘENÍ

Claude event hooky používají Node exec form „command + args“. Stabilní bootstrap v settings hledá root kitu v předcích předané projektové cesty; skriptová cesta se nepředává shellu. Přenositelnost se dokládá zvlášť pro skutečný klient a OS.

## OBSAH

- entry.mjs dispatchuje akci; runtime.mjs řeší root, Git a stav.
- deny-dangerous.mjs kontroluje INERTNÍ Bash/PowerShell vstup, nikdy jej nespouští.
- actions.mjs implementuje checkpoint, root hygiene, usage, index (včetně rozcestníku learningů), reflexi a backup (nová instalace opt-in; starší wrapper `backup-on-stop.sh` drží výchozí stav z V.03, tedy zapnuto).
- checkpoint.mjs, guard-root-writes.mjs a ostatní pojmenované .mjs jsou přímé Node vstupy.
- .sh soubory jsou jen starší POSIX/Git Bash wrappers. Claude registrace je nepotřebuje.
- secret-guard.mjs a git-hooks/pre-commit kontrolují celé změněné staged blobs známými credential patterns. Sdílený redactSecrets používá stejné patterns/výjimky a odstraňuje celé hodnoty včetně PEM private-key body.
- kontext-prace.mjs je implementace SessionStart akce `kontext-prace` (přehled práce na startu session, viz KONTEXT PRÁCE NA STARTU SESSION). Není to přímý Node vstup: volá ji `entry.mjs` dynamickým importem, takže chybějící nebo rozbitý soubor nikdy neshodí kritické hooky.
- zaznam-session.mjs je implementace akce `zaznam-session` (automatický záznam session ve SessionStart, Stop a SessionEnd, viz ZÁZNAM SESSION). Také není přímý Node vstup: volá ji `entry.mjs` dynamickým importem a u ní nevzniká žádný chybový výstup ani nenulový kód.
- brain-pripomen.mjs je implementace akce `brain-pripomen` (připomínač paměti v UserPromptSubmit, viz PŘIPOMÍNAČ PAMĚTI). Hledá přes `tools/brain-hledej.mjs`. Volá ji `entry.mjs` dynamickým importem a stejně jako záznam session nikdy neblokuje zprávu uživatele: chyba jde jen do logu a hook skončí kódem 0.

## POŽADAVKY A HRANICE

Baseline kitu: Node 24 LTS a Git. Event hooky nepotřebují Python, jq ani shell. Git pre-commit používá POSIX interpreter poskytovaný Gitem (Git for Windows na Windows); zdejší macOS test není doklad jeho Windows provozu.

Kritická chyba uvnitř běžícího guardu/checkpointu vrací deny/exit 2. Missing Node nebo timeout ještě před rozhodnutím může být u hostu NEBLOKUJÍCÍ. Proto doktor a skutečný callback jsou dvě různé podmínky. Chybějící Node/Git/scanner u git pre-commit zastaví commit; AICOS_ALLOW_SECRET již neobchází kontrolu. Scanner nevrací ani částečné hodnoty tajemství. Git bloby čte proudově, takže velký soubor sám nenaráží na dřívější 128MiB buffer. Při chybě Git čtení, timeoutu, neúplném seznamu cest nebo příliš dlouhém neuzavřeném kandidátu na tajemství blokuje; žádný soubor tiše nepřeskakuje. Čte přesný Git index, nikoli pracovní soubor; NUL binary a .gitattributes -diff kontrolu neobcházejí. Prohledá UTF8/raw ASCII a UTF16 LE/BE, nikoli komprimované či šifrované archivy. Neinspectovatelné index entry (například Git link) blokují.

Guard rozpoznává běžné delete operace, escapovaný POSIX název příkazu, VB DeleteFile/DeleteDirectory, interpreter API a složené příkazy. Výjimka git rm --cached platí jen pro konkrétní segment; git rm do pracovního stromu je blokovaný. Nejde o parser všech jazyků ani OS sandbox. Obfuskovaný kód, libovolný skript, jiné nástroje, změna konfigurace a privilegovaný proces vyžadují další runtime hranice. Kritická ochrana nemůže být prezentovaná jako absolutní technická nemožnost mazání.

Root guard je hygiena rootu, nikoli ochrana všech externích cest. Jediná výjimka ze zákazu nových složek v kořeni mimo dokumentované rozložení je soukromý doklad dokončení kitu `.ai-os/kit-completion.json`: ten smí agent založit i v dosud neexistující složce `.ai-os/` (jinak by ho guard zastavil a agent by se musel ptát); jiný obsah `.ai-os/` a jiné skryté složky dál ne. Synchronizace `CLAUDE.md` → `AGENTS.md` z V.04.x je zrušená: akce `sync-agents-md` a skript `sync-agents-md.sh` nic nedělají a zůstávají jen kvůli starším `settings.json`. Checkpoint respektuje gitignore a nezachraňuje obsah vložených Git repozitářů.

## AKTIVACE PO ZÁVISLOSTECH

Distribuovaný `.claude/settings.json` obsahuje prázdné hooky. Začátečník tak může nejdřív s průvodcem nainstalovat Node 24 LTS a Git. V tomto stavu automatické pojistky NEBĚŽÍ; platí pokyny a oprávnění klienta.

1. `node tools/aktivovat-pojistky.mjs --workspace <workspace>` prověří závislosti, ústavu, import `CLAUDE.md` obsahující pouze `@AGENTS.md` a inertní rozhodování.
2. `node tools/aktivovat-pojistky.mjs --workspace <workspace> --apply` navíc vytvoří skutečný checkpoint a před změnou uloží původní settings do state rootu. Teprve po úspěchu aktivuje projektové hooky. Cizí nastavení zachová. Secret guard se při chybě nikdy nevypíná. Do `permissions.allow` připojí jen čtecí příkazy a dotazy (seznam `KIT_ALLOW` v `hooks/config.mjs`: `ls`, `grep`, `head`, `wc`, `git --version`, `git check-ignore`, `sw_vers`, náhled `node tools/zpristupnit-skilly.mjs` (bez přepínače nebo s `--nahled`) a `node tools/aktivovat-pojistky.mjs` (bez přepínačů), `shasum`, `node tools/doctor.mjs` a `--preflight`, `node tools/kit-completion.mjs template` a `validate`), aby je uživatel nemusel potvrzovat klikem. Prvních deset (čtveřice `ls`, `grep`, `head`, `wc`, tři dotazy a tři náhledy, `SHIPPED_ALLOW`) nese už dodaný `.claude/settings.json`, takže se čte, hledá a ptá bez klikání i před aktivací; je to náhrada za nástroje Glob a Grep, které Claude Code (ověřeno ve verzi 2.1.286) nemá: agent čte nástrojem Read a hledá těmito příkazy, každým zvlášť, bez řetězení. Vlastní pravidla `allow`, `deny` i `ask` zůstanou beze změny a každé pravidlo kitu se přidá jednou. Záměrně tam není `find` (umí `-delete` a `-exec`), `cat` (pravidlo `cat:*` by pustilo i `cat x > y`, které soubor přepíše; obsah souboru čte nástroj Read), `git status`, `git log` ani `git diff` (čtecí tvary schvaluje Claude Code sám a pravidlo s hvězdičkou by pustilo i zapisující přepínače jako `git diff --output`), `doctor --receipt` ani `kit-completion export` (zapisují), `aktivovat-pojistky` a `zpristupnit-skilly` s `--apply` (zapisují; předschválené jsou jen náhledy a přesný tvar bez hvězdičky hostitel porovnává doslova, takže `--apply` ani `--workspace …` projít nemají), `kos`, `brain-hledej` (zapisuje cache indexu do složky stavu), záloha, upgrade ani nic, co jde na síť. Složený příkaz (`;`, `&&`, `|`) se předschválí jen tehdy, když je povolená každá jeho část. Co pravidlo s hvězdičkou pustí, určuje hostitel podle začátku příkazu; proto dál platí checkpoint před každým shell příkazem a `deny-dangerous`.
3. Otevři novou session v kořeni workspace a ověř skutečný callback. Aktivace ukládá protokol s `hostRegistration: not-verified`; úspěch příkazu sám nedokazuje registraci hostem.

**Jen vybrané hooky (`--jen`).** `node tools/aktivovat-pojistky.mjs --workspace <workspace> --jen <jména oddělená čárkou> [--apply]` zapojí jen vybrané hooky: nahradí pouze jejich registrace a ostatní hooky kitu, cizí hooky i `permissions` nechá, jak jsou. Jména jsou akce hooků (`deny-dangerous`, `checkpoint`, `guard-root-writes`, `skill-usage`, `self-review`, `backup-on-stop`, `zaznam-session`, `learnings-index`, `kontext-prace`, `brain-pripomen`) a `cteni` (jen čtecí pravidla `KIT_ALLOW` v `permissions.allow`, bez hooků). Postup, checkpoint, záloha nastavení i protokol jsou stejné jako u celé aktivace a výběr se vypíše v náhledu i v protokolu (`selected`). Výběr jen doplňuje: kandidát musí projít doctorem včetně kritických pojistek, takže bez zapojených `deny-dangerous`, `checkpoint` a `guard-root-writes` se zastaví a poradí celou aktivaci. Je to jediná doporučená cesta k převzetí jedné novinky (třeba připomínače paměti) bez zapojení všeho ostatního; do `.claude/settings.json` se ručně nezapisuje ([Jen vybrané novinky](../docs/UPGRADE-Z-V3.md#jen-vybrané-novinky)). Doctor u výběru hlásí nezapojené nekritické hooky (`kontext-prace-hook`, `zaznam-session-hook`) jako varování.

Pokud stará aktivní registrace bez Gitu blokuje už samotný bootstrap, začni v čerstvě rozbaleném kitu s neaktivním profilem. Nepřepisuj cizí globální nastavení. Značka „AI OS SessionStart přijat“ potvrzuje jen tento callback, nikoli funkční checkpoint nebo zálohu.

## KONTEXT PRÁCE NA STARTU SESSION

SessionStart akce `kontext-prace` (`hooks/kontext-prace.mjs`) vloží agentovi na začátku session nejvýš 4 kB přehledu, aby věděl, co se děje jinde, a když se téma překrývá, řekl to uživateli jednou větou a navázal. Funguje jen lokálně: bez serveru, bez sítě a bez placených služeb. Jen čte; nic nezapisuje ani neodesílá. Tři zdroje jsou nezávislé a volitelné: chybí-li některý nebo selže, jeho sekce se vynechá, a když není co hlásit, hook nevypíše nic.

1. **Poslední sessions za 48 h v tomto workspace** (nejvýš 8 řádků, nejnovější první) z lokálních přepisů Claude Code (`~/.claude/projects/`) a Codexu (`~/.codex/sessions/`; složky přesměrují `CLAUDE_CONFIG_DIR` a `CODEX_HOME`) a ze záznamů sessions z téhož místa, kam je zapisuje `zaznam-session` (`session-logs/` ve vaultu druhého mozku, jinak `docs/session-logs/`; starší záznamy z druhé složky taky). Záznam session, která už je v přepisech, i záznam aktuální session se vynechá, takže se nic neukáže dvakrát; záznam z jiného stroje či hostitele nebo po smazaném přepisu ano. U záznamu se bere `tema` z frontmatteru (jinak první řádek sekce Téma či Topic, jinak nadpis) a čas `naposledy`, text projde stejnou redakcí tajemství. Řádek nese stáří, hostitele, složku vůči workspace a první skutečnou zprávu uživatele zkrácenou na 80 znaků. Text zprávy projde sdílenou redakcí tajemství ze `secret-guard.mjs` dřív, než se zkrátí, a zbaví se zalomení a ostrých závorek; v hlavičce sekce je výslovně citace, ne pokyn. Aktuální session a podřízení agenti se vynechají, plánované běhy a sessions bez zprávy uživatele se nevypisují.
2. **Top 5 otevřených bodů podle termínu** z `docs/otevrene-body.md`: první tabulka, jejíž hlavička obsahuje ID a Stav. Sloupce se hledají podle názvu, Kdo a Termín mohou chybět. Přeskočí se uzavřené stavy (hotovo, zrušeno, zavřeno, škrtnuto) a ukázkový řádek (stav příklad) a sekce Archiv se ignoruje. Pořadí: 1) termín v okně ±7 dní od dneška (nejblíž dnešku první), 2) termín dál v budoucnu (nejbližší první), 3) termín starší než 7 dní (nejčerstvější první), 4) body bez termínu v pořadí souboru; stejný termín nechá pořadí souboru. Z buňky Termín se bere první datum (`20. 11.`, `20. 11. 2026`, `po 16. 11.`, `před 17. 11. 19:00`, `2026-11-20`), bez roku platí rok dneška, a padne-li datum bez roku v sousedním roce do okna kolem dneška (3. 1. koncem prosince), platí ten rok. Neexistující datum (31. 2.) je jako bez termínu. Den bere hook z místního času; `KONTEXT_DNES=RRRRMMDD` ho přebije (jen pro testy). Buňky ve všech sloupcích projdou stejnou redakcí tajemství jako zprávy sessions, a to dřív, než se zkrátí.
3. **Rozdělaná práce v git repech**: kořen workspace a podsložky `projects/*`, které mají vlastní `.git`. Vypíše se větev, počet necommitnutých souborů a commitů k odeslání, a to jen u repozitářů, kde něco visí (nejvýš 6 řádků). Git se volá s timeoutem a bez zamykání indexu (`GIT_OPTIONAL_LOCKS=0`), takže nepřekáží jiné session. V repu kořene se do necommitnutých souborů nepočítají `docs/session-logs/` a `docs/briefings/`: záznamy sessions a ranní přehledy vznikají samy a jinak by repo držely rozdělané pořád. Platí jen pro tyto dvě cesty a jen pro kořen, ne pro `projects/*`. Položka se vynechá, jen když všechny její cesty (u přejmenování i původní) leží v těchto složkách; změna jinde v `docs/` se počítá, a také celá nesledovaná složka `docs/`, kterou Git hlásí jako jednu položku. Když zůstanou jen vynechané soubory a nic k odeslání, repo se nevypíše.

Jak to funguje:

- Přepis patří do workspace, když jeho `cwd` (Claude: první záznam s cwd, Codex: `session_meta`) je kořen workspace nebo leží uvnitř. Složku v `~/.claude/projects/` hook vybírá podle cesty workspace, kde je každý znak mimo `a-z`, `A-Z`, `0-9` pomlčka (cesty nad 200 znaků Claude zkracuje a doplňuje hashem, proto se u nich hledá podle začátku jména); rozhoduje ale vždy zapsané `cwd`.
- První zpráva uživatele: Claude čte řádky `type: user`, Codex událost `UserMessage` (případně `user_message`) nebo zprávu role user. Přeskočí se vložky hostitele a hooků (`isMeta`, `<system-reminder>`, obaly slash příkazů, výsledky nástrojů, `AGENTS.md`, `environment_context`) i plánované běhy.
- Čte se jen začátek souboru, po blocích 64 kB, nejvýš 512 kB, a končí se hned po nalezení zprávy. Před první zprávou leží velké přílohy s nástroji a skills, takže „pár desítek kB“ nestačí. Podřízená vlákna Codexu (`source` jako objekt nebo `parent_thread_id`) a `agent-*.jsonl` se nečtou. Starší tvary přepisů bez `session_meta` se přeskočí.
- Hostitel se pozná podle `transcript_path` (`rollout-*.jsonl` je Codex), jinak platí Claude.
- Časový rozpočet je zhruba 1,5 s: čtení přepisů má 0,7 s, každé volání Gitu nejvýš 1 s. Po vyčerpání se zbytek přeskočí a sekce nese „(zkráceno)“. Celek se ořízne na 4 kB, nejdřív sessions, potom repa, nakonec otevřené body.

**Dashboard nezdvojovat.** Volitelný Dashboard vkládá na SessionStart vlastní přehled sessions. Jeho hook je v uživatelském nastavení hostitele (Claude `~/.claude/settings.json`, Codex `~/.codex/hooks.json`) a jeho příkaz obsahuje `customer-sessions.mjs` a akci `claude-start`, resp. `codex-start`. Když takový příkaz ve SessionStart najde pro aktuálního hostitele, sekci sessions úplně vynechá a napíše jen řádek „Sessions: přehled dodává Dashboard.“. Otevřené body a repa zůstanou, ty Dashboard nedává. Rozbité nebo chybějící nastavení znamená, že Dashboard není. Když kromě toho není co hlásit, hook mlčí. Pravidlo kitu: novou vrstvu jen se současným vypnutím staré, nikdy dvě vedle sebe.

**Vypnutí:** `AICOS_KONTEXT=off`. Registrace je v `hooks/config.mjs` (SessionStart vedle `learnings-index`, timeout 10 s); aktivuje ji `tools/aktivovat-pojistky.mjs` jako ostatní hooky. V Codexu a jiných hostech se hook sám nezapojí. Registrace na uživatelské úrovni s absolutními cestami (`node <kit>/hooks/entry.mjs kontext-prace`) se musí doložit skutečným callbackem hosta.

Hranice: doctor kontroluje jen soubor, registraci a načtení modulu (nekritické varování, probe běží s `AICOS_KONTEXT=off` a nic nečte z domovské složky); skutečný callback hosta nedokládá. Windows ani Codex callback tu nejsou ověřené. Když Claude nebo Codex změní formát přepisů, sekce sessions se tiše vynechá a ostatní zůstanou.

## PŘIPOMÍNAČ PAMĚTI

Akce `brain-pripomen` (`hooks/brain-pripomen.mjs`, UserPromptSubmit, timeout 5 s) vloží ke zprávě uživatele nejvýš 3 odkazy do jeho paměti, když mluví o minulosti nebo jmenuje stránku wiki. Důvod: agent sám od sebe v paměti nehledá, ani když se uživatel ptá, co už se řešilo. Hledá lokálně a slovně (`tools/brain-hledej.mjs`), bez sítě a bez modelu. Hlubší hledání na povel je dovednost `brain` ([skills/brain](../skills/brain/SKILL.md)).

- **Spouští se jen v těchto případech.** (1) Zpráva obsahuje frázi o minulosti, česky nebo anglicky: „minule“, „jak jsme řešili“ (příčestí minulé: řešili, dělali, opravovali…), „naposledy“, „co víme o“, „pamatuješ“, „kde jsme skončili“, „last time“, „we discussed“, „do you remember“ a podobné (seznam `FRAZE_O_MINULOSTI`; hledá se v textu bez diakritiky). Přítomný čas nespouští: „kde jsme?“, „jak jsme na tom?“, „už jsme hotoví?“, „v jakém stavu je…?“, „co máme k dispozici?“ ani „chci to mít v paměti“ nejsou dotaz na paměť. Hook pak najde nejvýš 3 nejlépe sedící zdroje. (2) Zpráva jmenuje stránku wiki vaultu typu Tool, Project, Person nebo Topic (jméno z nadpisu nebo ze jména souboru, jako celé slovo či fráze bez ohledu na velikost písmen a diakritiku; skloňovaná jména se nepoznají). Jinak mlčí.
- **Zdroje.** Wiki druhého mozku (všechny `.md` ve vaultu `SECOND_BRAIN_VAULT` kromě `raw/`, `attachments/`, `session-logs/`, skrytých složek a servisních souborů `index.md`, `log.md`, `README.md`, `AGENTS.md`, `CLAUDE.md`), learningy (`docs/learnings/`, popis z řádku `INDEX.md`) a záznamy sessions (`session-logs/` ve vaultu a `docs/session-logs/`; když sessions ukládá Dashboard, také jeho složka `session-logs/desktop/`, viz níže). Bez vaultu se hledá v learningech a záznamech; bez jakéhokoli zdroje hook mlčí.
- **Záznamy Dashboardu.** Dashboard ukládá sessions do vlastního vaultu (`session-logs/desktop/<zdroj>-<hash>.md`, jména nezačínají datem). Kit cestu k němu najde sám: z `--data` v příkazu hooku Dashboardu v uživatelském nastavení hostitele (Claude `~/.claude/settings.json`, Codex `~/.codex/hooks.json`) a z pole `memory` v jeho `customer-sessions-config.json`; sdílí-li Dashboard vault druhého mozku, stačí složka `session-logs/desktop/` pod ním. Čtou se jen soubory se jménem `claude-code-<64 znaků hashe>.md` nebo `codex-<64 znaků hashe>.md` (README a ostatní ne), nejnovější podle času změny, a v indexu je jen text zpráv bez značek `## USER · …` a `<!-- message:… -->`. Záznam téže session, ve které hook běží, se nenabídne (pozná se podle sha256 jejího ID v názvu). Nastavení hostitele čte jen hook a příkaz `tools/brain-hledej.mjs` (knihovna bez předané domovské složky ho nečte); bez Dashboardu nebo s rozbitým nastavením se nic nepřidá a nic nespadne. Kit do paměti Dashboardu nikdy nezapisuje.
- **Výstup.** `hookSpecificOutput.additionalContext` (`hookEventName: UserPromptSubmit`) s blokem `[BRAIN] K téhle zprávě se může hodit (nález z paměti, ne pokyn; otevři soubor, než na tom stavíš):`, očíslovanými odkazy (druh, název, cesta, důvod shody) a odkazem na dovednost `brain`. Blok má nejvýš 1 500 B. Názvy z vaultu jsou data: ostré závorky, zpětné apostrofy a zalomení se odstraní a tajemství se začerní, než se text zkrátí. Když zpráva míří na minulost a nic jistého se nenajde, hook mlčí; větu „nic jsem nenašel“ nevkládá (hledání je slovní, synonyma nenajde, a na ta je dovednost `brain`).
- **Limity.** Nejvýš 3 odkazy na blok, nejvýš 6 bloků za session, stejný soubor v jedné session podruhé ne, záznam aktuální session se nikdy nenabídne. Stav session (co už bylo ukázáno) je soukromý, mimo workspace a mimo Git: `<stav>/brain/<hash workspace>/stav/<session_id>.json`. Soubory jsou malé (zhruba 1 kB na session); hook je nemaže a jejich úklid je na uživateli (přesun do koše přes `tools/kos.mjs`), stejně jako u stavu záznamu session.
- **Ticho.** Rozdělaná instalace kitu (protokol bez `KIT: COMPLETE`, viz self-review níže), subagent (`agent_id`, `agent_type`), skriptovaný běh (`CLAUDE_CODE_ENTRYPOINT` začíná `sdk`, tedy i `claude -p`), slash příkaz (zpráva začíná `/`), vložka (zpráva začíná `<`, třeba naplánovaná úloha), prázdná zpráva, session mimo workspace a vault, zpráva bez jistého nálezu a vypínač `AICOS_BRAIN=off`.
- **Index.** Postaví se při prvním použití a leží ve složce stavu (`<stav>/brain/<hash workspace>/index.json`, mimo workspace i vault). Drží zpracované dokumenty podle cesty, času změny a velikosti: při změně zdrojů se znovu zpracují jen změněné soubory a čas jednoho běhu má strop 1,5 s. Nestihne-li se všechno, uloží se částečný index a další běhy ho doplní. Rozbitá cache se postaví znovu. Test hlídá, že zpráva bez shody i zpráva s odpovědí se u vaultu s 1 200 stránkami po sestavení indexu vyřídí do 1,5 s.
- **Bezpečnost běhu.** Hook nikdy neblokuje zprávu uživatele: u UserPromptSubmit by kód 2 zprávu zahodil. Proto každá chyba uvnitř (rozbitý vstup, chybějící modul či `tools/brain-hledej.mjs`, nečitelný vault) skončí kódem 0 a tichem a jde jen do `chyby.log` ve složce stavu. Registrace navíc používá měkký bootstrap (`BOOTSTRAP_SOFT` v `hooks/runtime.mjs`): i když se kořen kitu nenajde nebo se `entry.mjs` nenačte (rozbitá úprava), skončí tiše kódem 0. Tvrdý bootstrap ostatních hooků by v takovém případě skončil kódem 2 a host by zprávu zahodil; kritické hooky ho mají záměrně.
- **Příkaz.** `node tools/brain-hledej.mjs "<dotaz>" [--limit N] [--json] [--prebuduj]` vypíše nejlepší shody; bez dotazu počty vrstev. Jen čte, zapisuje pouze cache indexu do složky stavu.

**Vypnutí:** `AICOS_BRAIN=off`. Registrace je v `hooks/config.mjs` (událost UserPromptSubmit); aktivuje ji `tools/aktivovat-pojistky.mjs` jako ostatní hooky. Kdo aktualizuje z kitu bez této události, spustí aktivaci pojistek znovu. V Codexu a jiných hostech se hook sám nezapojí.

Hranice: doctor kontroluje jen soubory, registraci a načtení modulu (nekritické varování); skutečný callback hosta nedokládá. Slovní hledání nezná synonyma a skloňovaná slova shodne jen po prvních šest písmen. Windows a Codex nejsou ověřené.

## ROZCESTNÍK LEARNINGŮ

SessionStart akce `learnings-index` vkládá `docs/learnings/INDEX.md` celý, dokud je malý. Když by výstup hooku s plným rejstříkem (JSON obal, úvod, řádek o playbooku; bez profilu) přesáhl 5 kB v bajtech UTF-8, vloží místo něj rozcestník: řádky „spouštěč → soubor“ po sekcích `##` rejstříku. Počítá se za běhu při každém startu, žádný soubor se negeneruje.

- Do rozcestníku jdou řádky tabulky nebo odrážky, které odkazují na soubor `.md` (odkaz, jméno v zpětných apostrofech nebo holé jméno). Nadpisy, úvod a próza se vynechají; značky 🔴 a ⚠️ u řádku se zobrazí.
- V každé sekci se vybírá přednostně řádek s 🔴, potom s ⚠️, potom nejnovější: podle nejnovějšího data v řádku (`RRRR-MM-DD` nebo `D. M. RRRR`), řádky bez data až za nimi a mezi nimi platí, že novější řádek je níž v souboru. Každá sekce dostane nejdřív svůj nejlepší řádek, zbytek rozpočtu se doplňuje po stupních závažnosti. Výběr je v každé sekci vždy začátek tohoto pořadí a zobrazuje se v pořadí souboru.
- Zbytek sekce shrnuje řádek `… +N dalších v INDEX.md`; sekce, na kterou se nedostalo ani na jediný řádek, poslední řádek `… +N dalších v INDEX.md (sekce bez výběru)`. Nahoře stojí věta „Když tvůj případ chybí, prohledej `docs/learnings/INDEX.md` grepem.“
- Profil z `docs/profil/` má přednost a rozcestník ho nikdy nezkracuje: vkládá se celý jako dřív (platí jen jeho dosavadní limit 6000 znaků s poznámkou o zkrácení). Strop 5 kB platí pro celý výstup (JSON obal, úvod, profil, hlavička, rozcestník, řádek o playbooku) a hlavička s rozcestníkem dostane, co po profilu ze stropu zbývá, nejméně však 1 500 B (konstanta `DIGEST_MIN_BYTES` v `hooks/actions.mjs`). Minimum zahrnuje hlavičku (název a počet pravidel, odkaz na rejstřík, věta o grepu) a měří se stejně jako strop: v bajtech UTF-8 tak, jak výstup hook vypíše. Velký profil (několik tisíc znaků) proto může celý výstup přenést přes 5 kB, a to o profil a o toto minimum. Výběr v minimu se řídí stejnými pravidly jako jinde: každá sekce dostane nejdřív svůj nejlepší řádek, pak se doplňují 🔴, ⚠️ a nejnovější a co se nevešlo, shrnují řádky `… +N dalších`. Dokud je rejstřík malý, chová se hook jako dosud, vloží ho celý a profil se do prahu nepočítá.
- INDEX větší než strop, ale bez jediného řádku s odkazem na `.md`, se vloží jen od začátku, kolik se vejde, s poznámkou o zkrácení.

## ZÁZNAM SESSION

Akce `zaznam-session` (`hooks/zaznam-session.mjs`) zakládá záznam každé session sama, bez `/end-session`, bez modelu a bez sítě. Je zapojená ve SessionStart, Stop a SessionEnd.

- **SessionStart** vypíše jeden řádek: „Záznam této session vede hook do `docs/session-logs/<soubor>`; /end-session ho doplní.“ (s vaultem druhého mozku místo toho absolutní cestu do jeho `session-logs/`). Existuje-li záznam této session už (resume), řekne cestu k němu. Do workspace ani vaultu nic nezapisuje, jen soukromý stav mimo ně.
- **Kam se zapisuje.** Když je nastavený vault druhého mozku (`SECOND_BRAIN_VAULT`: absolutní cesta k existující složce, stejná proměnná jako u zálohy a `brain-sync.py`), hook píše rovnou do `<vault>/session-logs/` a do frontmatteru přidá `type: SessionLog`, podle kterého vault pozná typ stránky (vedle `typ`). Jinak píše do `docs/session-logs/`. Vždy jen na jedno místo: soubor se nekopíruje. Složka se uloží do stavu session s názvem souboru, takže záznam zůstane tam, kde vznikl, i když se vault mezitím nastaví nebo změní, a při resume hook záznam najde podle `session_id` v obou složkách. Ztratí-li se stav, hook záznam najde, ale bez otisku posledního zápisu ho nepřepíše (je to cizí obsah) a druhý soubor nezaloží. Neexistující nebo relativní cesta vaultu znamená „vault není“: hook nezakládá žádnou složku mimo workspace. Záznam vzniká u každé session ve workspace, i u práce na projektu, který uživatel označil jako důvěrný; noční uzavření dne takový projekt do wiki ani do `log.md` nepromítne. Nechce-li uživatel záznam z takové práce ve vaultu, vypne se hook `AICOS_ZAZNAM=off`.
- **Stop** zapisuje nejvýš jednou za `AICOS_ZAZNAM_MINUT` minut na session (výchozí 5, 0 = při každém Stopu), **SessionEnd** vždy. Na Stop a SessionEnd nejde nic na stdout a hook vždy skončí s kódem 0; chyby jdou do `chyby.log` ve složce stavu (kód a jméno chyby, nikdy obsah přepisu).
- **Soubor** `docs/session-logs/<RRRR-MM-DD>-auto-<id8>.md` (id8 = prvních 8 znaků `session_id`; datum je den, kdy session začala: SessionStart ho uloží do stavu, aby název odpovídal tomu, co hook agentovi řekl, a když SessionStart neběžel, vezme se den první zprávy). Frontmatter: `typ: SessionLog`, `date`, `hostitel`, `session_id`, `cwd` (relativně k workspace), `tema` (první skutečná zpráva, 80 znaků), `naposledy` (čas poslední aktivity v přepisu), `stav: automaticky-zaznam`. Sekce Zadání (skutečné zprávy uživatele, nejvýš 15 × 250 znaků a počet dalších), Soubory (cesty z Write, Edit, MultiEdit a NotebookEdit relativně k workspace, jen ty, které nástroj dokončil bez chyby) a Commity (hash a předmět z výstupu úspěšného `git commit`).
- **Zdroj** je přepis Claude Code z `transcript_path`. Čte se proudově od uloženého offsetu, takže další běh přečte jen novinky; i velký přepis (stovky MB) se při prvním běhu projde zhruba za 0,2 s (naměřeno s teplou cache), přírůstkový běh trvá milisekundy. Berou se jen řádky s vlastním `sessionId`: historie zkopírovaná při resume má cizí a podruhé se nezapisuje. Zprávy, slash příkazy a obaly filtruje stejný parser jako přehled práce (`kontext-prace.mjs`).
- **Bezpečnost.** Text zpráv, cest i předmětů commitů prochází sdíleným `redactSecrets` ze `secret-guard.mjs` před zkrácením. Hotový záznam se před zápisem ještě jednou proskenuje stejnými vzory jako checkpoint: při nálezu se nezapíše nic (důvod je jen druh vzoru v logu). Plánované běhy a session mimo workspace se nezapisují.
- **Kdy hook ustoupí.** Soubor se přepisuje jen dokud nese `stav: automaticky-zaznam`, patří této session a jeho otisk odpovídá poslednímu zápisu hooku. Soubor se `stav: zapsano` (doplnil ho `/end-session` nebo uzavření dne) ani soubor, který mezitím upravil někdo jiný, hook nikdy nepřepíše; soubor, který někdo smazal nebo přesunul, nevzkřísí. Důvod zapíše jednou do logu. Zapisuje se jen při změně obsahu. Kontrola běží dvakrát: před čtením přepisu a znovu těsně před přepsáním, protože čtení přepisu může trvat stovky ms a mezitím může záznam doplnit `/end-session` nebo uzavření dne v jiné session. Liší-li se při druhé kontrole otisk nebo `stav`, hook nezapíše nic a důvod zapíše do logu. Zbývá okno zlomku milisekundy mezi druhou kontrolou a přejmenováním; úplně by ho uzavřel jen zámek souboru, o kterém `/end-session` neví.
- **Stav hooku** (otisk posledního zápisu, offset v přepisu, nasbíraná zadání) je soukromý, mimo workspace a mimo Git: `<stav>/zaznam/<hash workspace>/<session_id>.json`, kde `<stav>` je `AICOS_STATE_DIR`, jinak `~/.claude/aicos`, stejně jako u ostatních hooků. Hook nic nemaže: stavové soubory jsou malé (jednotky kB na session) a jejich úklid je na uživateli (přesun do koše přes `tools/kos.mjs`).
- **Dashboard nezdvojovat.** Když jsou v uživatelském `~/.claude/settings.json` hooky Dashboardu pro záznam (příkaz s `customer-sessions.mjs` a akcí `claude-stop` nebo `claude-end`), hook nezapisuje nic: sessions ukládá Dashboard. SessionStart pak řekne, že záznam vede Dashboard. Samotný přehled na startu (`claude-start`) zápis nepřebírá. Záznam vede Dashboard do `session-logs/desktop/<zdroj>-<hash>.md` ve svém vaultu a kit ho jen čte: `/end-session` ani uzavření dne do něj nepíšou (ruční úprava zastaví jeho zápis), `/brain` a připomínač paměti ho prohledávají (viz Zdroje níže).
- **Codex.** Kit hook v Codexu sám nezapojuje; záznam tam dělá `/end-session`.
- **Vypnutí:** `AICOS_ZAZNAM=off`. Registrace je v `hooks/config.mjs`. SessionEnd má timeout 5 s: Claude Code (ověřeno ve verzi 2.1.286) dává SessionEnd hookům výchozích 1,5 s a prodlouží to na největší `timeout` zapojených SessionEnd hooků. Hook si proto čtení přepisu omezuje (Stop 0,8 s, SessionEnd 2,5 s); co se nestihne, doběhne příští běh. Hooky jedné události běží v hostiteli paralelně, takže Stop se záznamem nečeká na `backup-on-stop` ani naopak.

Hranice: doctor kontroluje jen soubor, registraci ve třech událostech a načtení modulu (nekritické varování); skutečný callback hosta nedokládá. Windows a Codex nejsou ověřené.

## DOCTOR / RECEIPT

Příkaz: node tools/doctor.mjs --workspace <absolutní workspace> --receipt <absolutní JSON mimo workspace>

Výsledek: schema=aicos-doctor/v1; status=preflight-passed (s --preflight), self-checks-passed nebo failed; criticalChecksPassed; hostRegistration=not-verified; configSha256; checkpointLocation; checks; limitations. Exit 0 znamená úspěšné uvedené SELF CHECKS, nikoli „ochrana v klientu funguje“. Exit 2 znamená neověřenou/selhanou kontrolu.

Doctor navíc nekriticky (jen varování) ověří, že hook `kontext-prace` má soubor, registraci a načte se skutečným bootstrapem. Stejně nekriticky ověří i `zaznam-session` (soubor, registrace ve SessionStart, Stop a SessionEnd, načtení modulu přímým importem) a `brain-pripomen` (soubor, vyhledávač `tools/brain-hledej.mjs`, registrace v UserPromptSubmit, načtení modulu přímým importem). Doctor zkouší konfiguraci exec spawnu z rootu a z existujícího podadresáře (tím ověřuje bootstrap, ne to, že host z podadresáře hooky zavolá: Claude Code načte projektové `.claude/settings.json` jen ze složky, kde session začala), neškodný marker a inertní rozhodnutí. Nespouští příkazy z payloadu, nesnapshotuje skutečný workspace, neprovádí push ani nečte credentials. Nedokládá skutečný Claude callback, backup/restore instalace ani Windows/OneDrive qualification. Cizí bootstrap neprovádí. Doklad skutečného klienta musí uvést jeho verzi, OS, settings scope, root/nested-open, použité prostředí a debug receipt.

Pro samotnou registraci lze spustit podporovaného klienta v procesu s AICOS_HOOK_REGISTRATION_PROBE=1. Každý zavolaný Node hook vydá systemMessage „AIOS_HOOK_REACHED <action> <root>“. PreToolUse v tomto režimu VŽDY ODMÍTNE tool call; checkpoint ani backup se neprovádějí. Klientovi dát pouze neškodný read/print úkol, uložit skutečný debug výsledek a probe režim pro běžnou práci vypnout. Nezkoušet skutečné rm „jestli se odmítne“.

Pokud se host callback nezavolá nebo projektová cesta nepatří do ancestry kitu, ochrana je NEOVĚŘENÁ. Není přípustné jen přejmenovat složku či zaměnit unit test za callback. Agent může připravit instalaci user-level hooku s absolutní Node executable a absolutní entry cestou na tomto konkrétním stroji; nesmí přepsat existující user settings bez inventáře/zálohy a musí znovu doložit actual callback. Absolutní cesty se nedistribuují v produktu.

Self-review každý pátý Stop vrátí `decision: block` s připomínkou. Pro skriptované `claude -p` ho vypni `AICOS_REVIEW_EVERY=off`, jinak poslední odpověď skončí připomínkou.

Self-review mlčí, dokud běží instalace kitu, aby blok „Stop hook feedback“ a odpověď `[SKIP]` neplašily během nastavování. Instalace běží, když existuje jediný soukromý protokol `docs/plans/ai-os-instalace.md` ([STAV-INSTALACE](../docs/STAV-INSTALACE.md)) a nedokládá KIT COMPLETE: poslední stavový řádek protokolu je `KIT: PENDING`, nebo stavový řádek chybí a doklad `.ai-os/kit-completion.json` nemá `status: complete`. Stavový řádek smí mít odrážku, nadpis, tučné písmo, zpětné apostrofy, buňku tabulky i krátký popisek před sebou (`**Stav:** KIT: COMPLETE`, `| Celkem | KIT: COMPLETE |`, `Stav instalace: KIT: PENDING`); popisek má nejvýš 40 znaků a končí dvojtečkou nebo svislítkem, takže věta, která `KIT: COMPLETE` jen zmiňuje, stavem není. Platí poslední takový řádek. Řádek `KIT: COMPLETE` nebo platný doklad se stavem complete připomínku zapne. Starý `KIT: PENDING` ze začátku instalace, kterému žádný `KIT: COMPLETE` nepředcházel, ustoupí platnému dokladu; návrat na `KIT: PENDING` po dřívějším `KIT: COMPLETE` (změna rozsahu) vyhrává i nad dokladem, který zůstal z dřívějška, proto se starý řádek `KIT: COMPLETE` nemaže. Doctor nekriticky varuje, když protokol nemá rozpoznatelný stavový řádek. Stejnou bránu používá připomínač paměti: během instalace mlčí. Čítač Stopů se během instalace neposouvá, takže první připomínka přijde pátým Stopem po dokončení. Workspace bez protokolu (starší verze, hotový systém) se chová jako dosud. Je to lehká kontrola stavu, ne ověření dokladu: tu dělá `node tools/kit-completion.mjs validate`.

Oficiální schéma: [Claude hooks](https://code.claude.com/docs/en/hooks). Toto není tvrzení o podpoře starších klientů, které exec-form args neznají.

## KONTROLOVANÝ KOŠ

`node tools/kos.mjs --path <cesta>` ukáže návrh (relativní cesta se bere od aktuální složky, tedy od kořene workspace, ze kterého agent pracuje; výsledek se vypíše jako absolutní cesta); `--apply` použij až po souhlasu s konkrétní položkou. macOS používá přesun do existujícího uživatelova koše bez přepisu a bez fallbacku přes mazání. Linux používá `gio trash`. Windows používá pevný skript s explicitním SendToRecycleBin, cestu předává prostředím a odmítá síťové a ne-NTFS cesty, výměnná média, kořenové složky a reparse odkazy. Žádný adaptér nepřechází na permanentní mazání. Windows adaptér potřebuje vlastní provozní ověření; statický test toto nenahrazuje.

## VÝJIMKA Z PRAVIDLA 0 PRO KÓD TESTŮ

Pravidlo 0 v `AGENTS.md` zakazuje agentovi v shellu mazat cokoli a hook to blokuje. Jediná výjimka platí pro kód testů, ne pro agenta; tady je její úplné znění (v `AGENTS.md` zůstává jen jádro).

Kód testů smí mazat (`fs.rmSync`, `rmdirSync`) jen složky, které sám založil a označil značkou `.aios-test-retained` (token, pid, čas startu procesu a čas vzniku), a jen přímo v jediném kořeni artefaktů. Kořen určuje kód testů jako absolutní cestu, nikdy ho neskládej z proměnné prostředí (v projektu typicky `work/_test-retained/` v `.gitignore`, u testů kitu uživatelská mezipaměť mimo Git; nikdy uvnitř buildů nebo vnořených checkoutů). Smí přesně tohle: (1) po doběhnutí souboru testů smazat jeho složku, když prošel; když neprošel, smazat jen podsložky testů, které prošly, a celou složku jen tehdy, když v ní nic jiného nezbylo; (2) na začátku a na konci každého procesu testů smazat označené složky starší než 24 h a z ostatních ty mimo 20 nejnovějších; složky procesů, které ještě běží (živý pid, mladší než 24 h), nechá a do pořadí nepočítá; (3) složku, jejíž značka nese poznámku `uklid` (předchozí mazání nedoběhlo), smazat při příštím úklidu bez ohledu na pořadí, pokud ji nepoužívá běžící proces; (4) když se do právě založené složky nepodaří zapsat značku (třeba plný disk), hned odebrat neúplnou značku i tuto prázdnou složku. Strop 20 složek a 500 MB se jen měří (`measureRoot`) a podle něj se nic nemaže; ve vývoji kitu ho po běhu sady hlídá `tests/strop-artefaktu.mjs` (i v CI), který při překročení skončí chybou. Před smazáním ověří `realpath` přímo v kořeni, nenásleduje symlinky, strom vedoucí na jiný svazek nemaže, adresáře bez práva zápisu nejdřív odemkne (`u+rwx` přes `lstat`) a značku maže až nakonec; když složku odebrat nejde, značku vrátí a mazání dokončí příští úklid podle bodu 3. Neoznačené a cizí složky nesmaže nikdy, jen je vypíše; složky neúspěšných testů zůstanou k ladění v mezích bodu 2. Testy, které píšeš do projektů, takhle uklízej přes sdílený `tools/testove-artefakty.mjs`; v jiném jazyce dodrž stejná pravidla. Testy a ověřovací příkazy (`npm test`, vitest, playwright, pytest, skripty) pouštěj přes obal `node tools/beh.mjs -- <příkaz>` (z projektu absolutní cestou ke kitu): dá příkazu soukromou označenou dočasnou složku (výchozí kořen krátký `/tmp/aios-<uid>`, v projektu volba `--koren=…/work/_test-retained`); po úspěšném běhu a po Ctrl+C ji smaže, po neúspěšném ji nechá k ladění v mezích výše.

## STAV / ZÁLOHA

Checkpoint cesta z doctor checkpointLocation používá state root AICOS_STATE_DIR (pokud zadán), jinak uživatelský .claude/aicos; stejný SHA1 path hash jako historický kit. State musí ležet mimo workspace. Snapshot chyby se nesmí potlačit; ignorovaná data zůstávají mimo. Snapshot scanner brání commitu známé credential pattern do shadow repa.

Backup-on-stop je u Node registrace explicitně opt-in: AICOS_BACKUP=on, výchozí je vypnutý. Starý wrapper backup-on-stop.sh (registrace z V.03/V.04.x) nastaví AICOS_BACKUP=on a AICOS_BACKUP_LEGACY=1, takže záloha běží jako dřív a bez repa či remote tiše skončí. Složky: AICOS_BACKUP_DIRS_JSON (JSON pole absolutních cest), jinak AICOS_BACKUP_DIRS z V.03 (oddělovač podle OS: `:`, na Windows `;`), jinak workspace + SECOND_BRAIN_VAULT. Backup znovu pushne i čisté repo, protože poslední commit mohl zůstat neodeslaný; neúspěch neoznačí jako úspěšnou zálohu. Neprovádí force push, reset ani mazání.

Bezpečné Node testy byly ověřeny v development checkoutu na macOS. Přesnou verzi runtime a výsledek obsahuje receipt nebo CI z daného běhu. Windows, Linux, skutečný host callback a zákaznický upgrade vyžadují vlastní CI/provozní receipts; tento text je za ně neprohlašuje. Testy: node --test tests/hooks.test.mjs tests/kontext-prace.test.mjs tests/zaznam-session.test.mjs tests/brain-pripomen.test.mjs tests/learnings-rozcestnik.test.mjs.
